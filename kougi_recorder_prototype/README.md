# 講義ノート録音 — 試作版

## GitHub Pagesで公開する手順（友達はGitHub不要）

### 1. GitHubでリポジトリを作る
1. マスター自身のGitHubアカウントで新しいリポジトリを作成します。
2. GitHub FreeでGitHub Pagesを利用する場合は、リポジトリをPublicにする方法が簡単です。公開リポジトリにはソースコードが見えるため、個人情報や秘密情報を置かないでください。
3. ZIPを展開し、`index.html`、`app.js`、`manifest.webmanifest`、`sw.js`、`README.md`をリポジトリ直下にアップロードしてコミットします。Gitのコマンドは必須ではなく、GitHubのWeb画面からファイルをアップロードできます。

### 2. GitHub Pagesを有効にする
1. リポジトリの **Settings → Pages** を開きます。
2. **Build and deployment** の **Deploy from a branch** を選びます。
3. ブランチを `main`、フォルダを `/(root)` にして保存します。
4. 公開完了後に表示されるURL（通常 `https://<ユーザー名>.github.io/<リポジトリ名>/`）をAndroid Chromeで開きます。
5. そのURLを友達に共有します。友達はGitHubアカウント不要で利用できます。

GitHubの画面名は変更される場合があります。最新の公式案内も確認してください：
https://docs.github.com/pages

## 試作版の機能
- 講義名・日付の入力
- MediaRecorderによる音声録音、録音の一時停止・再開・終了
- Web Speech APIによる日本語音声認識の表示
- IndexedDBへの講義情報・音声Blob・文字起こしの保存
- 保存した講義の一覧、音声再生、音声ファイル書き出し、テキスト書き出し、削除

## プライバシーと制限
- 録音ファイルと保存済み文字起こしは、各利用者のブラウザ内IndexedDBに保存します。利用者間で録音データを集約・共有するサーバーはありません。
- GitHub Pagesはアプリのファイルを配信するホスティングです。録音データをGitHubリポジトリへアップロードする処理は実装していません。ただし、GitHubはサイトのアクセス等に関するログを扱う可能性があります。
- `SpeechRecognition` / `webkitSpeechRecognition` はブラウザ提供の機能です。Chromeの実装では音声がGoogleなどの外部サービスで処理される可能性があります。アプリ側から正確な送信先や保持期間を確認・制御できません。機密情報や個人情報を含む講義では、利用規約と学校のルールを確認してください。
- IndexedDBは端末・ブラウザごとの保存です。サイトデータ消去、ストレージ圧迫、ブラウザ再インストール、端末故障で失われる可能性があります。大切なデータはエクスポートしてください。
- マイク利用にはHTTPS接続が必要です。GitHub PagesはHTTPSで配信されます。
- Android Chromeでの90分録音、画面ロック中の録音、端末別の音声形式、ストレージ上限、音声認識の連続動作は未検証です。まず短いテストから始めてください。
- 認識エンジンが終了・再起動する場合があります。文字起こしは完全な逐語記録ではなく、誤認識や欠落が起きます。
- 録音中の音声チャンクはメモリ上に蓄積され、終了時に保存されます。録音中にページがクラッシュすると、進行中の音声が失われる可能性があります。録音チャンクを逐次IndexedDBへ永続化する機能は未実装です。
- Service Workerによるキャッシュ処理は含まれますが、オフライン起動の信頼性やPWAとしてのインストール性は未検証です。

## ローカルテスト
PCにNode.jsがある場合、プロジェクトフォルダで次を実行できます。

```bash
npx serve .
```

`localhost` は開発用の安全なコンテキストとして扱われるため、マイクをテストできます。スマートフォンでの検証にはHTTPS公開URLを使ってください。
